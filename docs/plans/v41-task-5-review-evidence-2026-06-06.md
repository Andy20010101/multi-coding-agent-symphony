The active provider allowlist remains `claude-code-cli` and `codex-cli`. `commandTemplateFor()` rejects other provider ids. The tests cover Gemini/inactive-provider rejection without invoking the process runner.

The worker evidence records both active providers through the backend runner path. I did not find evidence of raw `claude`, raw `codex`, Kiro, Gemini, DeepSeek, or arbitrary shell fallback being used as provider evidence.

The remaining risk is that main verification or release closeout may still want a successful controlled provider completion in an authenticated/faster local environment, but that is not a blocker for reviewing this task-5 backend evidence addition.
