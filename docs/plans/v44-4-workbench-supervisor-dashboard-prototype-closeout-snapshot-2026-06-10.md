## Known risks

The prototype still depends on the v44.3 read model shape. If the v45 backend changes field names, the projection layer needs a targeted update before the page should be pointed at live v45 data.

The fixture fallback is useful for visual QA, but it is not proof that a live supervisor route is healthy. The route state and `source` text need to stay visible so operators can tell whether they are looking at live data or fixtures.

The static Workbench JS bundle is generated and large. PR-5 only refreshes it from `pnpm workbench:build`; future review should focus on source files first and treat the static asset as build output.

Mobile still requires scrolling to reach detailed cards after the header and route metadata. The first viewport now exposes the command boundary and active scenario state; the full Current Gate, Timeline, and Ownership details remain lower in the stack by design.

## Rollback path

If the PR-5 layout fix causes a regression, revert the PR-5 commit. That removes the CSS adjustment, this snapshot, and the regenerated Workbench static bundle.

If only the snapshot text is wrong, revert this document.

If v44.4 needs to be rolled back beyond PR-5, revert PR #33 first, then #32, #31, #30, and #29 in reverse merge order. Do not compensate by adding backend execution routes or browser command controls.
